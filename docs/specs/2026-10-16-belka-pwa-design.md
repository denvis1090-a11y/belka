# Белка — мобильное веб-приложение (PWA)

Дата: 2026-10-16
Статус: на согласовании

## 1. Цель

Перенести готовую игру «Белка» (сейчас это один файл `belka.html`, опубликованный как артефакт) в самостоятельное мобильное веб-приложение. Игру открывают по ссылке в Safari или Chrome на телефоне и ставят на главный экран. Дальше она работает как приложение: своя иконка, запуск без панелей браузера, игра без интернета, продолжение партии после закрытия.

**Для кого.** Игроки в белку в Казахстане. Основные устройства — iPhone и Android-смартфоны, только в вертикальном положении.

**Что сказал пользователь:**
- мобильное веб-приложение, только вертикальная раскладка, iPhone и Android;
- хостинг на GitHub Pages;
- в первую версию входят офлайн и установка на экран, сохранение партии.

**Мои допущения (можно поправить):**
- адрес вида `<аккаунт>.github.io/<репозиторий>/`, поэтому все пути в приложении относительные;
- игра, правила, боты, дизайн и тексты переносятся как есть, без изменений;
- сборщика нет, это обычные статичные файлы.

## 2. Критерии готовности

1. Приложение проходит требования браузера к установке: есть манифест с иконками 192 и 512, зарегистрирован Service Worker, страница отдаётся по HTTPS. На Android Chrome предлагает «Установить», на iPhone приложение добавляется через «На экран "Домой"» и запускается без панелей Safari.
2. После первого открытия приложение полностью загружается без интернета: страница, стили, код, иконки. Шрифты работают офлайн, если хотя бы раз загрузились онлайн, иначе подставляется системный шрифт.
3. Если закрыть приложение посреди раздачи или выгрузить его из памяти, при следующем запуске партия продолжается с того же места: те же руки, взятка, счёт глаз, настройки, язык.
4. Замер раскладки без перекрытий и вылезаний за экран проходит на восьми размерах: 320×568, 360×640, 360×800, 375×667, 390×844, 412×915, 430×932 и компьютер 1440×900. Боком телефон показывает просьбу повернуть его.
5. Отступы от выреза камеры и полоски «домой» задаёт сама страница. В режиме приложения содержимое не залезает под системную строку iPhone.
6. Прогон партий ботов проходит без ошибок: очки раздачи всегда в сумме 120, первая раздача даёт 2 глаза, «яйца» дают 4.
7. В консоли браузера нет ошибок при запуске, игре и работе офлайн.

## 3. Что входит и что нет

**Входит в версию 1:**
- разделение кода на модули;
- полноценная страница `index.html`;
- манифест, иконки, офлайн-кеш;
- сохранение и восстановление партии;
- кнопка «Установить» (Android) и подсказка для iPhone;
- уведомление о новой версии;
- запрет масштабирования, обновления потягиванием и выделения текста;
- тесты движка в Node;
- репозиторий и инструкция по публикации.

**Не входит (позже):**
- игра по сети с живыми людьми;
- звуки и вибрация;
- запрет гаснуть экрану;
- push-уведомления;
- аккаунты;
- публикация в App Store и Google Play;
- заставки запуска для iPhone (startup images);
- набор правил «Жезказган»;
- собственные копии шрифтов вместо Google Fonts.

## 4. Структура проекта

```
belka-pwa/
  index.html              страница приложения, все мета-теги
  manifest.webmanifest    описание приложения для установки
  sw.js                   Service Worker: офлайн-кеш и обновления
  css/app.css             весь дизайн (из belka.html)
  js/engine.js            правила и боты, без DOM
  js/i18n.js              тексты RU/KZ
  js/storage.js           чтение и запись localStorage
  js/game.js              ход партии: фазы, таймеры ботов, подсчёт
  js/ui.js                отрисовка и обработка нажатий
  js/app.js               запуск, офлайн-кеш, установка, обновления
  icons/icon.svg          исходник иконки
  icons/icon-180.png      apple-touch-icon для iPhone
  icons/icon-192.png      иконка для Android
  icons/icon-512.png      иконка для Android
  icons/maskable-512.png  иконка Android с запасом под круглую обрезку
  tests/engine.test.mjs   прогон партий ботов в Node
  tools/                  скрипт генерации PNG-иконок
  docs/specs/             это описание
  README.md               как запустить локально и опубликовать
  .nojekyll               чтобы GitHub Pages не обрабатывал файлы
  belka.html              исходный файл-артефакт, остаётся для справки
```

Код подключается как ES-модули (`<script type="module" src="js/app.js">`). Их поддерживают Safari 14+ и Chrome 61+ — это все актуальные iPhone и Android.

## 5. Модули и их границы

| Модуль | Отвечает за | Даёт наружу | Зависит от |
|---|---|---|---|
| `engine.js` | Колода, очки, старшинство, правила хода, раздача, взятки, пересдача, три уровня ботов | `PRESETS`, `RULE_KEYS`, `presetOf`, `team`, `id`, `pts`, `eff`, `nextP`, `stepOf`, `makeDeal`, `legal`, `applyPlay`, `collect`, `handsEmpty`, `eligible`, `chooseCard`, константы мастей | ничего |
| `i18n.js` | Все тексты на двух языках | `T`, `eyeWord` | ничего |
| `storage.js` | Безопасная работа с localStorage: настройки, язык, сохранение партии, флаг «подсказку iPhone закрыли» | `loadSettings`, `saveSettings`, `loadLang`, `saveLang`, `loadGame`, `saveGame`, `clearGame`, `getFlag`, `setFlag` | `engine.js` (для проверки правил) |
| `game.js` | Состояние партии `S`, фазы (`botRedeal`, `askRedeal`, `play`, `trickEnd`, `dealEnd`, `gameOver`), таймеры ботов, подсчёт глаз, пауза при открытых окнах | `start(saved?)`, действия (`humanPlay`, `nextDeal`, `redeal`, `keepHand`, `newGame`, `setLang`, `applySettings`), подписка `onChange(cb)`, `getState()` | `engine.js`, `i18n.js`, `storage.js` |
| `ui.js` | Отрисовка всех экранов и окон, обработка нажатий, анимации | `mount(rootEl, game)` | `game.js`, `engine.js`, `i18n.js` |
| `app.js` | Запуск: восстановить партию, смонтировать UI, зарегистрировать Service Worker, показать «Установить», подсказку iPhone, уведомление о новой версии | — | все |

`engine.js` не трогает DOM и таймеры, поэтому тест запускает его в Node напрямую. Логика партии (`game.js`) сейчас живёт в `belka.html` вместе с отрисовкой и переносится без изменения поведения. Меняется только одно: вместо прямого вызова `render()` она сообщает об изменении через `onChange`.

## 6. Страница и манифест

**`index.html`, `<head>`:**
- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`. Масштаб не блокируется (это нужно для доступности), двойное касание гасится через `touch-action: manipulation`.
- `<meta name="theme-color" content="#0c0e12">`.
- `<meta name="apple-mobile-web-app-capable" content="yes">` и `<meta name="mobile-web-app-capable" content="yes">`.
- `<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">`: содержимое идёт под системной строкой, отступ даёт `env(safe-area-inset-top)`.
- `<meta name="apple-mobile-web-app-title" content="Белка">`, `<link rel="apple-touch-icon" href="icons/icon-180.png">`, `<link rel="manifest" href="manifest.webmanifest">`.
- `<title>Белка</title>`, `<meta name="description">` на русском.
- Google Fonts подключаются так же, как сейчас.

**`manifest.webmanifest`:**
- `name`: «Белка — карточная игра Казахстана», `short_name`: «Белка»;
- `start_url`: `./`, `scope`: `./`, `id`: `./`;
- `display`: `standalone`, `orientation`: `portrait`;
- `background_color` и `theme_color`: `#0c0e12`;
- `lang`: `ru`;
- `icons`: 192 и 512 с назначением `any`, плюс 512 с назначением `maskable`.

**Безопасные зоны.** Раньше их добавляла обёртка артефакта, теперь это делает сама страница: `html { padding: env(safe-area-inset-top) 0 env(safe-area-inset-bottom) }`, `html, body { height: 100% }`, `box-sizing: border-box` на `html`. Боковые отступы уже считаются через `max(16px, env(safe-area-inset-left/right))`. Окна (`.ov`) и заглушка поворота уже учитывают отступы сами.

**Поведение как у приложения.** `overscroll-behavior: none` на `html` и `body` убирает обновление потягиванием. `-webkit-touch-callout: none` и `user-select: none` на игровом поле запрещают меню при долгом нажатии и выделение. `touch-action: manipulation` убирает задержку и зум по двойному касанию.

## 7. Офлайн-кеш (Service Worker)

- **Версия.** Константа `VERSION` в `sw.js`, кеш называется `belka-<VERSION>`. Каждый выпуск меняет `VERSION`.
- **Установка.** Заранее кешируются `./`, `index.html`, манифест, CSS, все JS-модули и иконки.
- **Активация.** Кеши `belka-*` с другой версией удаляются, после чего вызывается `clients.claim()`.
- **Запросы:**
  - переходы по страницам (`mode: navigate`): сначала сеть с таймаутом 3 секунды, при неудаче — `index.html` из кеша;
  - файлы того же сайта: сначала кеш, затем сеть;
  - `fonts.googleapis.com` и `fonts.gstatic.com`: кеш `belka-fonts` по схеме «отдать из кеша, обновить в фоне»;
  - всё прочее идёт мимо кеша.
- **Обновление.** Новый Service Worker устанавливается и ждёт. Страница замечает это (`registration.waiting` / `updatefound`) и показывает внизу «Доступна новая версия — Обновить». По нажатию она шлёт `SKIP_WAITING`, ловит `controllerchange` и перезагружается. Партия восстанавливается из сохранения.
- **Регистрация** идёт только при наличии `serviceWorker` в `navigator` и не с `file://`.

## 8. Сохранение партии

- **Ключ** `belka-save`, значение `{ v: 1, savedAt, S }`. Здесь `S` — полное состояние партии вместе с текущей раздачей `S.d`.
- **Когда пишем:**
  - после каждого изменения состояния, но не чаще раза в 300 мс;
  - сразу при `visibilitychange` → `hidden` и при `pagehide`: на iPhone выгрузка из памяти не даёт других событий.
- **Чтение при запуске.** Если `v === 1` и у `S` есть `d`, `rules`, `eyes`, `phase`, запускаемся с этого состояния. Таймер нужной фазы (ход бота, сбор взятки, пересдача бота) запускается заново. В любом другом случае сохранение стирается и начинается новая партия.
- **Не сохраняются** открытые окна правил и настроек.
- **Окончание партии.** Когда партия кончилась (`gameOver`), сохранение остаётся, чтобы итог можно было увидеть. Кнопка «Новая партия» его перезаписывает.
- **Ошибки localStorage** (приватный режим, переполнение) молча пропускаются: игра работает, просто без продолжения.

## 9. Установка

- **Android и компьютерный Chrome.** Ловим `beforeinstallprompt` и откладываем его. В шапке появляется кнопка-значок «Установить», по нажатию вызывается `prompt()`. После `appinstalled` кнопка прячется.
- **iPhone и iPad в Safari, если приложение не установлено** (`navigator.standalone !== true` и нет `display-mode: standalone`). Через 20 секунд после начала первой партии внизу появляется карточка: «Установите Белку: нажмите "Поделиться" и выберите "На экран Домой"», с кнопкой «Понятно». После закрытия она больше не показывается (флаг в localStorage).
- **Тексты** для обоих случаев есть на русском и казахском.

## 10. Иконки

Исходник `icons/icon.svg`: тёмно-синий фон бортика, на нём бирюзово-зелёный вертикальный овал сукна с золотой прострочкой, в центре белая карта с золотым «қошқар мүйіз». Для `maskable` всё значимое помещается в центральные 80%.

PNG делает скрипт в `tools/`. Сначала пробую Python с Pillow. Если его нет — скрипт на Node с самописным PNG-кодировщиком (встроенный `zlib`), который рисует те же простые фигуры. Иконки лежат в репозитории готовыми, и сборка для публикации не нужна.

## 11. Проверка

1. `node tests/engine.test.mjs`: сотни партий ботов на всех трёх наборах правил и уровнях. Проверяется сумма 120, ровно 2 глаза за первую раздачу, ровно 4 за «яйца», отсутствие зависаний.
2. Локальный сервер (`python -m http.server`) и встроенный браузер:
   - замер раскладки на восьми размерах из раздела 2 (тот же скрипт, что раньше);
   - нет ошибок в консоли;
   - манифест читается;
   - Service Worker в состоянии `activated`.
3. Офлайн: открыть, дождаться кеша, остановить сервер, перезагрузить — игра загрузилась.
4. Сохранение: сделать несколько ходов, перезагрузить страницу — та же раздача и тот же счёт.
5. Обновление: поменять `VERSION`, перезагрузить — появилось «Доступна новая версия».
6. На живом iPhone и Android проверяет пользователь после публикации. Список, что смотреть, будет в README.

## 12. Публикация

- В папке проекта делается `git init` и первый коммит.
- README объясняет шаги:
  1. создать репозиторий на GitHub;
  2. `git push`;
  3. Settings → Pages → Deploy from a branch → `main` / `(root)`;
  4. открыть `https://<аккаунт>.github.io/<репозиторий>/` на телефоне.
- В GitHub пользователя ничего не отправляется без отдельного согласия. Создать репозиторий и отправить код через `gh` можно только по явной просьбе.

## 13. Риски

- **Хранилище на iPhone.** Safari может стереть данные сайта, который не открывали около 7 дней. Для установленного на экран приложения это реже, но возможно. Это не ломает игру: просто начнётся новая партия.
- **Шрифты при самом первом запуске без сети** будут системными. Решается собственными копиями шрифтов, это в списке «позже».
- **Поворот экрана на iPhone** манифест не запрещает. Остаётся заглушка «поверните телефон».
- **Казахские тексты** нужно показать носителю языка (давняя пометка).
